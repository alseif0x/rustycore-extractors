# Explicit collision disk-world resource capability

`linux-collision-disk-world-resources-v1` is an explicit 64-bit opt-in carried
by the six actual private spool owners. Constructors default to `BoundedV1`;
its original ceilings remain unchanged. Mixed resource policies reject before
world/model/map acquisition or archive output. The independently explicit
captured-volume capability retains its own checks.

The profile raises cumulative capacities, while preserving per-file/parser /
format admission, complete-input policy, the combined logical 2 GiB ceiling and
all component memory/allocation-overlap guards. Configured fields only reduce
their profile maximum. Repeated-row list plans/builders bind a separately named
work profile; complete list codecs and native artifact formats are unchanged.

heap 1 GiB and each selected-model/package logical heap 2 GiB. Existing lower
component ceilings still constrain composite operations. Counters do not measure
RSS, every allocator operation or all CPU work.

## Subsequent cache admission correction (2026-10-12)

The expanded package matrix exposed a conservative admission conflict: two
64 MiB descriptor ceilings plus the 512 KiB guard allowance leave less than
128 MiB inside the disk profile's 256 MiB inventory ceiling. Reserving the
previous 128 MiB cache parser allowance rejected even a small own-tile cache.
The disk profile now defaults to a reduced 64 MiB cache parser allowance.
No memory, active-body, parser or cumulative ceiling is raised. Earlier
resource evidence remains historical; the later current-v8 executable-source report accepts this correction. See
`forever-collision-leased-archive.md` for exact scope and hashes.

The full-workspace attempt also retained a directory-metadata test failure:
a newly created name can share the captured timestamp. That test now forces
a changed timestamp. LocalStore's production directory guard remains
metadata-only and does not authenticate a full directory-name snapshot.
