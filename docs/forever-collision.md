## M2 collision contract

`M2Collision::parse(bytes, limits)` finds the first bytewise `MD20` marker,
requires its complete 304-byte header, and interprets collision offsets
relative to that marker. A later marker never rescues an invalid first one.
This is not an MD21 container parser or a validator for unrelated M2 sections.
The source checks no M2 version field in this path.

| Header field | Byte offset relative to MD20 |
| --- | ---: |
| Collision bounds, six f32 values | 188 |
| Collision sphere radius, unused | 212 |
| Index count and offset | 216 / 220 |
| Vertex count and offset | 224 / 228 |
| Normal count and offset, unused | 232 / 236 |

The field named `nBoundingTriangles` is an index count. Source indices are
u16; vertices contain three f32 components. With zero indices, parsing returns
`None` after checking the complete header, without interpreting unused counts,
offsets or bounds. Otherwise counts, extents, triangle divisibility, index
references, finite emitted floats and ordered declared bounds must validate.
Bounds need not enclose the vertices: the source copies the declared box.
Valid overlapping arrays and unaligned offsets are admitted.

Limits only decrease: 64 MiB input, 1,000,000 vertices, 3,000,000 indices and
32 MiB raw output. Views borrow source bytes; errors expose static codes.
No partially validated geometry or partial output vector escapes.

Sources: `src/tools/vmap4_extractor/modelheaders.h:24–94` and
`model.cpp:37–158`.

## Raw single-M2 contract

The writer emits magic `VMAP04E\0`, one group, `ModelFlags::IsM2`, copied
bounds and the pinned zero/default fields. Each triangle changes index order
from 0/1/2 to 0/2/1 and expands indices to u32. The original reader and writer
apply inverse coordinate transforms; finite vertex bits, including signed
zero and subnormal values, therefore survive unchanged in the raw output.

The `INDX` block deliberately declares `4 + 2 × index_count` while physically
writing `4 + 4 × index_count` bytes. The original assembler ignores that
declared length and reads u32 indices. The Rust writer preserves this
historical inconsistency; its reader validates it explicitly. Total size is
`100 + 4 × index_count + 12 × vertex_count`, with exact EOF.

`RawM2::parse` admits this single-M2 subset and its original u16 index domain.
It is not a general raw WMO reader. In particular, the u32 at raw offset 8
is not universally a vertex total: the M2 exporter writes a vertex count,
while WMO export accumulates triangle counts and the assembler discards it.

Sources: `model.cpp:88–158`, `wmo.cpp:393–406,499–540`,
`vmapexport.cpp:278–296` and `vmap4_assembler/TileAssembler.cpp:475–594`.

## WMO root, group and geometry foundation

The public `forever_vmap::wmo` API has four stages:

1. `Root::parse(bytes, limits)` validates complete root framing and exposes
   borrowed chunks, MOHD fields, GFID references and doodad metadata.
2. `Group::parse(bytes, limits)` validates a complete group with its 68-byte
   MOGP header and framed children, retaining geometry, batches, MODR and MLIQ.
3. `resolve_contexts(&root, &[GroupInput { file_data_id, group }], limits)`
   checks the complete ordered group inventory and resolves skips/split IDs.
4. `GroupContext::project_geometry(limits)` returns owned collision geometry,
   or `None` for an explicitly skipped group. A group with no selected faces
   produces a successful empty geometry value.

GFID must follow MOHD. Its shape must exactly match group count and declared
LOD count; when the LOD flag is set with count zero, the source defaults to
three LODs. The detailed group inventory uses LOD zero, omits zero FDIDs and
retains duplicates and order. Missing GFID does not invent a filename fallback.
GFID and record accessors check index arithmetic and bounds.

Skip checks retain source precedence: unreachable flag, antiportal flag, then
the exact case-sensitive `antiportal` name. Name offsets that the source would
dereference must be nonnegative and reach a NUL terminator. Split group IDs
use one mutable forward pass: an earlier parent's inherited ID is visible,
a later parent's original ID is visible, and a skipped parent's ID is unchanged.
Invalid signed split references leave the original ID intact; this is not
recursive graph resolution.

Both MOPY/MPY2 triangle records and MOVI/MOVX indices are supported. The face
predicate is `flags & 0x08 != 0 || (flags & 0x20 != 0 && flags & 0x04 == 0)`.
Selected vertices are compacted in original vertex order; their f32 bits,
triangle order and winding survive unchanged. Geometry retains group flags,
resolved ID, bounds and the original MOBA batch values without recomputing
batches after filtering.

MODS/MODD and MODN or MODI remain structural source data, with checked set
spans and finite spawn transforms. MODN names are NUL-terminated bytes, not
assumed UTF-8 or filesystem paths. No acquired-model validity set is inferred.
MLIQ preserves exact dimensions, position, signed material, vertex records
and tile bytes. These source views permit zero dimensions without inventing
a vertex/tile relationship. Emitted raw liquid has additional consumer bounds
described below; dependency acquisition and validated selection are separate
stages documented below.

### WMO admission and resource policy

The Rust parser is deliberately stricter than the unchecked C++ reader:
complete framing, unique consumed chunks, exact record extents, exclusive
alternative arrays, valid indices, finite geometry/liquid/spawn floats and
ordered bounds are required, including data later filtered or skipped. The
declared MOGP container bounds its children; the source instead adjusts its
cursor by 68 bytes. Unknown chunks remain opaque. MVER is optional and, when
present, must contain one u32; its value is retained without a version gate.
These checks do not establish malformed-input parity with C++.

`wmo::Limits` permits reductions, including zero, from 64 MiB per input,
4,096 chunks per file (outer and child chunks together), 1,000,000 vertices,
3,000,000 indices, 1,000,000 groups and 1,000,000 metadata records per checked
array. Context construction and each geometry projection have a separate
64 MiB allocation ceiling. The latter includes renumbering scratch and all
live vector capacities; it does not count borrowed input, allocator overhead
or previously returned values retained by the caller. No partial result is
returned, and data-bearing views omit Debug output; errors expose static codes.

## WMO liquid projection

`wmo::liquid::project(&root, &group, &lookup)` returns a borrowed `Liquid`
with flags, mapped type and an optional source `LiquidView`. The caller's
`LiquidLookup` supplies type-to-material u8 IDs and material u32 flags. These
are the same facts exposed by the closed terrain LiquidType/LiquidMaterial
DB2 readers and their materialization rules. The local QA caller connects
their materialized values to this trait; the pure converter and acquisition
collector require a caller-supplied lookup. Missing type/material rows do not
mark a liquid as ignored, and lookup results must stay stable during projection.

The pinned rules are preserved:

- Root flag `0x4` maps the header liquid ID directly. Otherwise header ID 15
  becomes zero; every other ID gets a wrapping u32 increment before mapping.
- Legacy IDs 1–20 map in a four-value cycle to 13/14, 14, 19 and 20. The
  first category becomes 14 when group flag `0x80000` is set; otherwise it
  becomes 13. Zero and IDs at least 21 pass through unchanged.
- An admitted nonzero header type sets flag `0x2`. MLIQ adds flag `0x1`.
  With type zero, the first tile whose low nibble differs from 15 supplies
  a legacy type from `nibble + 1`; this does not retroactively set `0x2`.
- Material flag `VisualOnly = 0x2` suppresses liquid. The MLIQ check also
  consults type zero and clears both output flags when ignored. Thus flags
  0, 1, 2 and 3 are distinct valid outcomes.

Projection preserves the mapped type for diagnostics even when ignored;
only flag `0x1` exposes a serializable view. It does no allocation, acquisition
or group skipping. Source facts: `wmo.cpp:254–263,315–341,543–557`,
`vmapexport.cpp:312–321,510` and `Maps/MapDefines.h:111–115`.

## Raw WMO conversion and strict reader

`wmo::raw::convert(&root, &groups, &lookup, ConversionLimits)` accepts the
complete ordered `GroupInput` inventory and returns `Option<ConvertedWmo>`.
It revalidates source limits, resolves contexts, and retains each visited
group's liquid decision once, including skipped groups. Two deterministic
geometry passes compute sizes and serialize; the second never repeats liquid
lookups. A checked geometry subtotal rejects an impossible output budget as
soon as at least one collision triangle exists, before projecting later groups.

The 24-byte raw header contains `VMAP04E\0`, **total collision triangles** at
offset 8, emitted group count, root WMO ID and model flags zero. Groups retain
resolved IDs, flags and bounds, followed by `GRP `, `INDX`, `VERT` and optional
`LIQU`. INDX retains the declared two-byte/physical four-byte index anomaly.
LIQU stores its type and, for flag `0x1`, the exact packed 30-byte source
header, one f32 height per vertex and tile bytes. Flag `0x2` alone stores only
the type. Unskipped empty groups remain present when another group has faces.

If total triangles are zero, conversion returns `None` and no raw file should
be created, even if liquids or doodads exist. This matches the native raw-file
removal decision. It does **not** determine doodad-dependent extraction success.
It remains valid with output cap zero; no raw consumer gate is imposed on
liquid that will never be emitted.

`ConversionLimits` only reduces its source `wmo::Limits`, 64 MiB output cap
and 256 MiB live allocation cap. The combined budget charges context and plan
vector capacities, the one output allocation, and each current geometry's
arrays and renumbering scratch. Geometry is released between groups. Borrowed
inputs, caller-owned lookup storage and allocator overhead are excluded.
No partial vector escapes on failure, and outputs pass `RawWmo::parse` before
being returned. Data-bearing types have no Debug implementation.

`RawWmo::parse(bytes, limits)` is borrowed and allocation-free. It checks
header/group totals, exact EOF, tags and declared sizes, flags 0–3, bounds,
finite values, index references and liquid shape. WMO indices use the u32
domain, including values beyond the M2 u16 domain. It verifies the bounded
format rather than reconstructing source compaction or liquid lookup decisions.

Emitted MLIQ requires `xtiles * ytiles > 0` and
`xverts * yverts == (xtiles + 1) * (ytiles + 1)`, with checked arithmetic.
No equality per axis is imposed. The native assembler allocates height storage
from tile dimensions before reading the vertex product: a larger product
would overflow it; a smaller one leaves an uninitialized suffix. Zero tiles
also fail its `fread(ptr, 0, 1)` check. This is a stricter consumer-admission
policy, without narrowing `Group`/`LiquidView` source parsing. Ignored liquid
and header-only flag `0x2` do not use this MLIQ gate.

Sources: `wmo.cpp:175–192,369–541`, `vmapexport.cpp:255–311`,

## Pure WMO doodad selection

`wmo::doodads::requests(&root)` borrows the validated root without allocation.
Each request contains a `name_index` and either `Target::Name(&[u8])` or
`Target::FileDataId(u32)`. MODN enumerates every NUL-terminated name in physical
order using its byte offset, including empty or unreferenced names. MODI uses
the physical ordinal and omits only zero FDIDs; repeated targets remain requests.

`resolve(&root, &groups, valid_name_indices, limits)` reparses sources under
the caller's reducible limits and validates the complete group inventory.
The supplied valid indices must identify actual requests, not interior string
offsets or zero MODI slots. Arbitrary caller order and repeated valid indices
are admitted. Sorted membership checks avoid quadratic row comparisons.

Only non-skipped groups contribute MODR references, including groups with no
collision faces. Out-of-range spawn references and spawns whose name was not
validated are omitted. The owned `Selection` retains sorted unique u16 spawn
references and set ranges. Its allocation budget includes live contexts,
membership scratch, references and ranges; `resident_bytes()` reports retained
vector capacities. Borrowed source bytes and allocator overhead are excluded.

`Selection::outcome(has_geometry)` distinguishes collision success, successful
doodad-only extraction, and failed no-collision extraction. Without geometry,
both a nonempty MODS table and nonempty valid reference set are required.
An M2 parser's `None` is not a valid doodad: the acquiring caller admits a name
only after producing positive M2 raw collision output. `set_references(set)`
visits set zero then a requested valid nonzero set, preserving repeated
occurrences across overlapping sets without duplicating a vector. Sorting
does not claim the byte order of the original unordered reference container.
WMO doodad transforms and placement orchestration are supplied by the separate
placement and collision bridge APIs described below.

Source facts: `wmo.cpp:77–151`, `vmapexport.cpp:255–310` and
`model.cpp:211–307`. Nineteen focused synthetic tests cover these policies.

## Direct MDDF/MODF placements and dir_bin

`forever_vmap::placement` projects supplied direct placements without I/O:

- `Mddf::parse(bytes, limits)` borrows exactly one 36-byte source record;
  `Modf::parse(bytes, limits)` borrows exactly one 64-byte record.
- `project_m2(&source, assigned_id, name, Context, limits)` and
  `project_wmo(...)` return a `Placement` that borrows only the supplied name
  and owns its numeric bit patterns. `Context` contains `map_id`,
  `original_map_id` and `global_wmo`.
- `encode(&[Placement], limits)` validates the entire supplied sequence and
  returns one complete byte vector. `DirBin::parse(bytes, limits)` validates
  the entire stream before exposing its borrowed `records()` iterator.

IDs and already-normalized names are caller inputs. The module allocates no
placement IDs, normalizes no names, acquires no models and performs no
collision-validity filtering. Source ID fields and direct-FDID predicates are
exposed for later orchestration; they do not resolve a source name or FDID.

| Source field | MDDF byte offset | MODF byte offset |
| --- | ---: | ---: |
| Source ID / unique ID, u32 | 0 / 4 | 0 / 4 |
| Position / rotation, three f32 each | 8 / 20 | 8 / 20 |
| Lower / upper bounds, three f32 each | Absent | 32 / 44 |
| Flags, u16 | 34 | 56 |
| DoodadSet / NameSet, u16 | Absent | 58 / 60 |
| Scale, u16 | 32 | 62 |
| Direct-FDID source flag | `0x40` | `0x8` |

Source flags not consumed by these projectors remain opaque. MODF DoodadSet
is retained without expanding doodads or checking it against a WMO set table.
All consumed source position/rotation/bounds floats must be finite and bounds
ordered. These are explicit stricter policies than the native unchecked data
access and `strlen` writes. Names must contain 1–500 non-NUL ASCII bytes;
the API does not verify whether the caller actually normalized them.

Both projectors permute source position `(x,y,z)` to `(z,x,y)` and preserve
rotation bits unchanged. MDDF always uses `Scale / 1024.0f`, including zero;
its NameSet is zero and `global_wmo` has no effect. MODF permutes both bounds,
uses `Scale / 1024.0f` only with source flag `0x4` (otherwise exactly 1), and
truncates the u16 NameSet to its low byte. Zero scale remains admitted. The
supplied assigned ID is preserved without inferring native allocation order.

Global WMO adds `(533.33333f * 32, 533.33333f * 32, +0.0f)` to position and
both bounds using three f32 additions. The third addition is required: it
changes a negative zero to positive zero in this source operation. Output
flag `0x1` denotes bounds, `0x2` is set when map IDs differ, and MODF source
flag `0x1` adds output flag `0x4` (path-only). MDDF only emits the parent bit.

The `dir_bin` stream has no magic, count or padding. Each record contains u8
flags, u8 NameSet, u32 ID, three position words, three rotation words, one
scale word, optional six bound words, then u32 name length and raw name bytes.
All numeric words are little endian. Size is **38 + name length** without
bounds or **62 + name length** with bounds. The codec permits flags 0–7 and
uses only the bound bit to select the physical shape; it does not infer model
class from that bit. It preserves record order, duplicate IDs and finite f32
bits, validates exact EOF and admits an empty stream. Invalid later records
cannot yield a successfully parsed prefix.

`placement::Limits` only reduces defaults of 64 MiB per operation, 1,000,000

and projection borrow data; encoding checks complete size and actual vector
capacity before returning. Stack, caller-retained inputs and allocator
overhead are outside that logical byte cap. Errors expose static codes and
data-bearing values omit Debug output.

## Bounded local collision collector

The public `forever_casc::collision` API is:

1. `Extractor::new(&mut LocalStore, &lookup, Limits)` shares one already
   admitted local store and a stable caller-owned liquid lookup.
2. `extract(ModelRequest::{M2,Wmo}(InputRef::{FileDataId,LogicalName}))`
   acquires complete files and returns a `ModelHandle`.
3. `finish()` rechecks source guards and returns an owned `Extraction` only
   after every request succeeds. Any request error poisons the collector;
   subsequent requests and finish fail, including after `InputChanged`.

The collector publishes no files and returns no partial extraction. A finished
result owns raw buffers, model source facts and WMO metadata: complete root
bytes, name-to-model bindings, selected references/set ranges and ordered group
source facts. Root views are reconstructed from owned bytes, without
self-referential storage. Handles expose stable insertion ordinals. Model
statuses distinguish `Collision`, M2 `NoCollision`, and WMO `DoodadOnly`.

WMO processing eagerly requests every MODN/MODI dependency, including names
not referenced by any spawn. It then acquires all nonzero detailed GFID groups
in source order, including groups later skipped by geometry projection.
Only positive M2 collision results validate doodad names. An acquisition or
conversion failure stops the operation; available dependencies never rescue
an incomplete selected root/group or failed batch.

Requests have explicit routing types. FDIDs reject zero and `u32::MAX` and
use `FILEXXXXXXXX.xxx` output basenames. Logical names require explicit
`LocalStore::enable_names`; they do not fall back to numeric routing if their
text resembles `FILEXXXXXXXX.xxx`. The original CascLib name path has that
compatibility fallback (`CascOpenFile.cpp:351–353`); this API deliberately does
not. No FDID-to-name, locale, layout or remote fallback is added.

ASCII logical names are bounded to 1,024 bytes. M2 legacy `.mdx`/`.mdl`
extensions are rewritten before lookup, retaining the source `M`/`m` case;
basename normalization and canonical cache identity are separate operations.
The acquisition name API retains its own stricter path/hash policy. WMO group
basenames are rejected as root requests. Reuse requires the same model class
and canonical origin. Different origins sharing a normalized basename,
cross-class aliases and recursive pending entries fail explicitly, rather
than reusing whichever output name was first inserted by the native cache.

All ceilings only reduce. Defaults are 64 MiB per file; 4,096 reads, models,
explicit requests and dependency requests each; 256 MiB cumulative acquired
bytes; 256 MiB retained raw lengths; and a 1 GiB combined logical budget for
store resident memory, collector capacities and current read/conversion
scratch. Dependency requests count MODN/MODI cache hits too; MODI zero slots
do not count. Source bytes are not refunded when buffers are released, while
reused raw models count once. Source and conversion limits remain in force.
Caller-owned liquid lookup storage, stack and allocator overhead are outside
the collector counter; it is not an RSS guarantee.

assembler searches the actual effective-parent chain for the **first present

terminal. It does not skip a mismatch, reorder a parent payload or borrow a
more distant matching payload. Own and mixed tiles also receive complete

## Model and instance ray queries

The pure `query` API operates on complete validated `vmo::View` values. It does
not acquire models or load a map package. `Ray::new`/`from_bits` retain finite
origin/direction values and signed zeros, require at least one nonzero direction
component and never normalize. Component reciprocals may be infinite. Public
maximum distance accepts nonnegative values, including positive infinity; it
rejects NaN, negative values and negative infinity. Distance is a ray parameter,
not necessarily physical length.

`model::intersect` queries local model coordinates. `Instance::new` validates a
bounded placement and retains its precomputed transform; `Instance::intersect`
queries that model in internal VMAP coordinates. `model::instance` is the
one-shot equivalent. The caller supplies the model-to-placement binding.
`Result<Option<Hit>, Error>` separates failure from a miss and exposes hit
distance bits plus group and triangle ordinals without geometry-bearing Debug.

### Source operations and numeric admission

The immutable reference is `02245dcd245e7433e524577656177723d3e4992e`:
`WorldModel.cpp:34–81,390–505`, `ModelInstance.cpp:27–65`,
`BoundingIntervalHierarchy.h:89–229`, and G3D Matrix3, Ray and
CollisionDetection helpers. This is an authored implementation of those
reviewed operations; the upstream implementations remain external.

- Triangle tests are two-sided. They reject `abs(determinant) < 1e-5`, preserve
  inclusive barycentric edges and admit only `t > 0 && t < current_maximum`.
  Equal distances and exact maximum endpoints do not replace a hit.
- Group queries use their mesh BIH without a declared-group-box prefilter.
  A single group bypasses the group BIH; multi-group models traverse it.
  Empty worlds return a miss without traversing a group tree. `ignore_m2`
  checks the world IsM2 flag. Path-only placement filtering is not part of the
  original ModelInstance method and is not added here.
- `Mode::Any` stops in the source traversal order. `Mode::Nearest` retains the
  strictly nearest admitted hit. Neither mode changes ray direction or sorts
  candidate geometry independently of the stored hierarchy.
- Instance rotation uses the source f32 Z*(Y*X) construction and general
  cofactor inverse, not a transpose shortcut. The candidate-plane AABox gate
  rejects only a returned positive infinity; it does not compare box time to
  the supplied maximum. Origin subtraction precedes inverse rotation and
  inverse-scale multiplication; direction receives inverse rotation only.
- Scale must be finite and nonzero with a finite reciprocal. Negative scales
  are admitted: their local maximum may be negative or negative infinity,
  preserving the source comparisons. Zero scale, singular transforms and
  unsupported nonfinite derived arithmetic return errors. Positive-infinite
  public maxima remain supported; no lossy normalization or numeric repair is
  performed.

`Limits` only reduces defaults of **16,000,000 node visits** and **16,000,000
triangle tests**, including reductions to zero. A single `Budget` is shared
across nested group/mesh traversal and successive calls. Work is charged before
the next node/triangle operation; exhaustion is an error rather than a miss.
The walker uses at most **65 stack entries per nested tree**, with no query
heap allocation. Executing an unsafe phantom/dead edge marked by infinity
returns `UnsafeTraversal`, with no full-scan fallback. These counters measure
Rust traversal work; they do not claim exact original counters, all CPU work,
input-reader allocations or a process RSS ceiling.
